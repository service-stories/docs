This guide takes you from an API key to a blog post you can publish. You use `curl`, but any HTTP client works.

## Prerequisites

- A User API key. See [Authentication](/authentication) to get one.
- At least one completed service ticket with a blog story in your company.

Save your API key in an environment variable so the examples below can use it:

```bash
export SS_API_KEY="your-user-api-key"
```

<Warning>
  Keep your API key on your server. Never put it in browser code or a public repository.
</Warning>

## Fetch your first blog post

<Steps>
  <Step title="Check your API key">
    Call `GET /me` to confirm your API key works and see the companies it can access.

    ```bash
    curl https://api.servicestories.com/api/developer/v1/me \
      -H "x-user-api-key: $SS_API_KEY"
    ```

    The response lists your user and companies:

    ```json
    {
      "id": "108",
      "firstName": "Sam",
      "lastName": "Lee",
      "companies": [
        { "id": "7", "name": "Acme Plumbing" },
        { "id": "12", "name": "Northside Auto Repair" }
      ]
    }
    ```

    If you get a `401`, check that you copied the full key and sent it in the `x-user-api-key` header.
  </Step>
  <Step title="Pick a company">
    List the companies your API key can access, then note the `id` of the one you want. You pass it as `companyId` when you list tickets and stories.

    ```bash
    curl https://api.servicestories.com/api/developer/v1/companies \
      -H "x-user-api-key: $SS_API_KEY"
    ```
  </Step>
  <Step title="Find a ticket with stories">
    List completed tickets that already have stories for that company:

    ```bash
    curl "https://api.servicestories.com/api/developer/v1/service-tickets?companyId=7&hasStories=true" \
      -H "x-user-api-key: $SS_API_KEY"
    ```

    Note the `id` of a ticket in `items`.
  </Step>
  <Step title="Find the ticket's blog story">
    List the ticket's stories for the blog channel:

    ```bash
    curl "https://api.servicestories.com/api/developer/v1/service-stories?companyId=7&ticketId=5012&platform=blog" \
      -H "x-user-api-key: $SS_API_KEY"
    ```

    The list returns summaries only, without the content. Note the story's `id`.
  </Step>
  <Step title="Get the full story">
    Fetch the story to get its content:

    ```bash
    curl https://api.servicestories.com/api/developer/v1/service-stories/9031 \
      -H "x-user-api-key: $SS_API_KEY"
    ```

    ```json
    {
      "id": "9031",
      "version": 2,
      "updatedAt": "2026-11-20T15:04:12.000Z",
      "platform": "blog",
      "status": "draft",
      "title": "Why your water heater makes a popping sound",
      "slug": "why-your-water-heater-makes-a-popping-sound",
      "contentHtml": "<p>A popping sound usually means sediment has built up...</p>",
      "featuredImage": "https://api.servicestories.com/api/public/media-assets/331/water-heater.jpg",
      "seoTitle": "Water heater popping sound | Acme Plumbing",
      "metaDescription": "Learn what causes a popping water heater and how a flush fixes it.",
      "structuredData": "{\"@context\":\"https://schema.org\",\"@type\":\"BlogPosting\"}"
    }
    ```

    The response above is shortened. See [Get a service story](/api-reference/service-stories/get-a-service-story) for every field.
  </Step>
  <Step title="Publish it">
    Map the fields to your website:

    | Field | Use it as |
    |---|---|
    | `title` | The post title |
    | `contentHtml` | The post body. It doesn't include the `<h1>`, so your site's title isn't repeated. |
    | `featuredImage` | The featured image. Image URLs are public, so you can link to them or download them. |
    | `slug` | The post URL |
    | `seoTitle`, `metaDescription` | The SEO title and meta description |
    | `structuredData` | JSON-LD as a string. Put it as is in a `<script type="application/ld+json">` tag in the page `<head>`. |

    Reading a story doesn't change it in Service Stories.
  </Step>
</Steps>
